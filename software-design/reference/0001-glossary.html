Glossary

Terms are used exactly like this in every lesson. See Lesson 1.

Module: anything with an interface and an implementation. A function, class or package.
Interface: everything a caller must know to use the module, including side effects and error behaviour.
Implementation: the code inside that keeps the interface's promises.
Deep module: small interface, lots of behaviour behind it.
Shallow module: interface nearly as complex as what it does.
Classitis: too many tiny classes, each hiding little.
Deletion test: delete it in your head. Complexity vanishes = pass-through. Complexity reappears in callers = earning its keep.
Information hiding: a module keeps its design decisions private so the implementation can change without breaking callers. Information leakage is the opposite.
Bring together / keep separate: group code that shares information, does a related task, repeats a pattern or needs the same handling. Separate code that shares little. Lesson 2.
Ubiquitous language: one rigorous vocabulary shared by developers and domain experts, used in talk, docs and code. Lesson 3.
Bounded context: an area where one model and one language are consistent. A new context starts where the language changes.
Polyseme: one word with several meanings in different groups (Fowler's example: "meter").
Glossary: the written list of agreed words, with the words to avoid.
Characterization test: a test that records what the code actually does now, so you can spot unintended change. Lesson 4.
Seam (Feathers): a place where you can change behavior without editing in that place. Where a module's interface lives.
Enabling point: where you choose which behavior a seam uses (for example, real or fake).
